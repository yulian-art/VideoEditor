# 板书对齐工作台 0.4.1 中文使用手册

## 1. 工作原理

输入板书视频、原始旁白和可选字幕/CSV。录音是固定的成片时间基准，改变板书不会移动录音或字幕。原板书视频中的声音不用于成片。

每个锚点记录录音目标时间 `target` 和原视频时间 `source`。普通区间在相邻锚点间线性插值；相邻 source 相同表示定格。独立 `cuts` 记录让 source 在某个 target 处向前跳变，预览与导出共用映射。

自动粗调用本地 ASR、OCR 和语义模型生成候选，再由人工核对；候选多或覆盖高不等于成片正确。

## 2. 安装 Python 与 FFmpeg

建议 Windows 10/11、64 位完整 Python 3.12、近期 Chrome/Edge。核心编辑器声明支持 Python 3.11 以上；本版分析安装脚本使用 3.12，其他平台和依赖组合没有同等验证。

| 组件 | 人工编辑 | 自动粗调 | 导出 |
| --- | --- | --- | --- |
| 完整 Python，含 Tcl/Tk | 必需 | 必需 | 必需 |
| FFmpeg，含 libx264/AAC | 波形和兼容预览需要 | 抽帧需要 | 必需 |
| requirements-analysis.txt 依赖 | 不需要 | 需要 | 不需要 |
| 本地 Whisper/OCR/E5 模型 | 不需要 | 视输入缓存而定 | 不需要 |

按 [Python 官方 Windows 说明](https://docs.python.org/3.12/using/windows.html)选择完整安装器，不要用缺少 Tk/venv 的嵌入式包替代。检查：

```powershell
py -3.12 --version
py -3.12 -m tkinter
```

第二条应弹出窗口，可关闭。文件选择器依赖 Tcl/Tk。

从 [FFmpeg 官方下载入口](https://ffmpeg.org/download.html#build-windows)选择 Windows 构建，解压后记住 `ffmpeg.exe` 完整位置。检查：

```powershell
& "D:\Tools\ffmpeg\bin\ffmpeg.exe" -version
& "D:\Tools\ffmpeg\bin\ffmpeg.exe" -hide_banner -encoders
```

选择具备 `libx264` 的构建。`h264_nvenc` 另需 NVIDIA 硬件与驱动，首次导出先用 CPU。无需将 FFmpeg 放进源码目录，也可加入 PATH。

完整解压源码 ZIP 到可写目录，预留模型、缓存和导出空间。源码包不含 Python、模型和 FFmpeg。本文路径是示例，均须替换为自己的路径。

## 3. 首次启动与退出

双击 `run.cmd`，或在源码根目录的 PowerShell 中运行：

```powershell
.\run.cmd
```

多版本 Python 建议明确指定：

```powershell
py -3.12 app.py --ffmpeg "D:\Tools\ffmpeg\bin\ffmpeg.exe"
```

程序监听本机随机端口，自动打开带访问令牌的浏览器地址。保留终端，可从终端复制地址重新打开。不要向公网转发服务或分享带令牌的 URL。

手动开浏览器可用：

```powershell
py -3.12 app.py --no-browser --port 8765
```

端口冲突时换一个。退出前先“保存项目”，再关闭页面并在终端按 Ctrl+C。关闭浏览器不等于停止服务，也不会自动保存。

## 4. 准备自动粗调环境

仅做 CSV 人工细调可跳过。首次安装需要网络。在源码根目录运行：

```powershell
.\setup-analysis.cmd
```

脚本使用 Python 3.12 创建 `.analysis-venv`，安装固定版本依赖，并下载固定提交的 E5 ONNX 模型到 `models/e5-small`，逐文件校验 SHA-256。它不安装 FFmpeg，也不准备 Whisper 模型。任一步失败应先解决再继续。

等价分步命令：

```powershell
py -3.12 -m venv .analysis-venv
.\.analysis-venv\Scripts\python.exe -m pip install -r requirements-analysis.txt
.\.analysis-venv\Scripts\python.exe scripts\download_semantic.py
```

例如下载多语言 small Whisper 模型：

```powershell
.\.analysis-venv\Scripts\python.exe -c "from faster_whisper.utils import download_model; download_model('small', output_dir='models/whisper-small')"
```

这是安装示例，不保证特定速度或准确率。已有兼容模型可复用，选择包含模型文件的目录而非单文件。参见 [faster-whisper 官方仓库](https://github.com/SYSTRAN/faster-whisper)。

RapidOCR 首次初始化可能下载资源，可提前联网执行：

```powershell
.\.analysis-venv\Scripts\python.exe -c "from rapidocr import RapidOCR; RapidOCR(params={'Global.use_cls': False}); print('OCR initialized')"
```

在界面“自动粗调 → 本地分析设置与已有缓存”中设置：

| 设置 | 填写 |
| --- | --- |
| 分析 Python | 新建的 .analysis-venv\Scripts\python.exe 完整路径 |
| 本地 Whisper 模型目录 | models\whisper-small 的完整路径 |
| 本地语义模型目录 | models\e5-small 的完整路径；默认安装位置也可自动识别 |
| 已有分析库目录 | 正常虚拟环境留空；独立依赖目录才需分号分隔填写 |
| 仅使用缓存 | 第一次不勾选 |

未配置语义模型时可进入旧词汇匹配模式，结果和完整语义路线不同，应看实际分析方法/日志。离线前需分别准备 Whisper、OCR、E5；安装 Python 包不代表模型齐全。

## 5. 创建项目和导入素材

建议在自己的工作目录保存原视频、原 AAC/M4A、字幕与项目副本，不覆盖唯一原始文件。

右侧“项目素材”选择：
1. “板书视频”：原始视频。
2. “旁白录音”：固定时基的 AAC/M4A。
3. “转写字幕”：可选 JSONL / JSON / SRT，时间属于该旁白。
4. “FFmpeg”：自动检测失败时选择可执行文件。

**新页面没有项目时，“载入素材并生成波形”不可点。** 选择一种创建路线：

- 自动路线：先填素材和分析设置，点“开始 / 重新粗调”创建项目。
- CSV 路线：先选好素材，再点顶部“导入 CSV”载入对齐表。
- 恢复路线：点“打开项目”，选择已有 `.align.json`。

有项目后，修改素材/字幕路径需点“载入素材并生成波形”。先核对画面、录音、时长、波形、字幕属于同一份素材。

JSON 相对媒体路径以项目文件目录解析。移动文件后可重新选择素材、载入并另存。AAC 逐包校验要求 MP4/M4A 容器中的 AAC 原文件；WAV/MP3 若事先转成 AAC，之后只能证明与新 AAC 一致，不能证明与转码前原包一致。

## 6. CSV 格式和导入

`examples/anchors.csv` 是当前格式示例。基本两列为“录音时间（成片）”“原板书时间”；完整导出还保存下列信息：

| 列 | 意义 |
| --- | --- |
| 录音时间（成片） / 原板书时间 | target / source |
| 内容 / 核对方式 | 实际为两个独立列，用于说明和证据 |
| 至下一锚点的画面倍速 | 按相邻点计算，不依赖手工填写 |
| 锚点ID / 来源 / 锁定 / 置信度 | 稳定身份及保护状态 |
| 记录类型 / 裁剪源起点 / 裁剪源终点 / 裁剪录音位置 / 裁剪数据JSON | 独立裁剪及暂存点 |

时间支持秒数、`mm:ss`、`hh:mm:ss`，可带小数。建议 UTF-8；应用导出带 BOM，便于表格软件识别。避免软件将时间列转日期。

target 必须严格递增；普通 source 可相等表示定格，但不能向后倒退。源跳变用独立裁剪记录，不用同一 target 下两个普通点。末尾 target 应与旁白实际时长一致。

```csv
录音时间（成片）,原板书时间
00:00:00.000,00:00:00.000
00:00:06.000,00:00:06.000
00:00:16.000,00:00:20.000
00:00:20.000,00:00:20.000
```

此例最后 4 秒保持 source 20。用于其他录音时需改末点。CSV 不是完整项目备份，不包含全部字幕、候选和核对状态。

## 7. 60 秒与 20 秒自动粗调

1. 选择自己的视频、录音，确认模型和分析 Python。
2. “截图间隔（秒）”设为 **60**，点“开始 / 重新粗调”。
3. 完成后查看摘要、匹配候选、待核对列表，核对几个可靠点并保存项目。
4. 需要更多板书证据时改为 **20** 重跑。新增帧需额外 OCR，耗时和缓存增长；不保证必然更准确。
5. 继续人工核对和细调。

“候选加密抽帧上限”默认 24，控制候选附近额外抽帧预算，不是全片候选数量。“OCR 裁边”顺序为左、上、右、下，单位对应缩放后的分析图像像素；默认分析宽度 1180，先全零再调整，不能直接使用未经换算的原视频像素。

重跑只替换**未锁定自动点**，人工、CSV、边界和已锁定点保留。新候选仍需检查与原点的冲突。

置信分不是正确概率。内容支撑覆盖表示 accepted 内容点附近有证据支撑的范围，不代表对齐准确率；起终点、定格、跨度很长的插值不算内容证据。不能靠降低阈值、强配未知画面来提高真实覆盖。

### 7.1 缓存复用与失效

默认 `.analysis-cache`，可指定别的目录。相同身份的数据可复用；60/20 秒设置不同会产生对应任务和新增抽帧需求。

0.4.1 语义缓存键包含 worker 实现摘要、算法配置、模型/分词器摘要，以及 Python、NumPy、ONNX Runtime、tokenizers 和执行环境身份。每条文本独立推理，避免 INT8 结果依赖同批文本集合。

旧 v1 语义缓存明确失效并保留，不直接迁移为 v2。升级代码、模型或运行时可能需要冷跑。“仅使用缓存”缺少当前身份的数据会失败，取消勾选后重新生成；不要复制旧库或篡改身份绕过检查。

缓存通常含课程文本和本机路径，不要公开提交。任务记录位于 `.analysis-cache/jobs/<任务ID>/`，缓存不是项目备份。

### 7.2 已有转写/OCR

“转写字幕”用于显示字幕；“转写缓存”是自动分析输入，二者用途不同。分析转写输入用 JSON/JSONL，SRT 走字幕入口。OCR 缓存应保存真实源时间与识别内容。

建议先让应用生成自己的缓存，再参考其格式接外部工具。外部缓存不能完整证明素材来源，需自行保证它来自当前视频/录音，不能混用。模型目录或普通 SRT 不应填进 OCR 缓存栏。

## 8. 匹配候选和待核对区间

点击候选或待核对项会进入源帧核对状态，**按该项保存的 source 直接定位原板书帧**，不是用当前成片映射反推画面。界面显示期望源时间和实际帧时间；编码帧粒度可能有差异，以实际帧为准。

1. 看真实板书内容是否和候选录音一致。
2. 听对应录音；核对画面保持不动，录音与字幕沿固定时基走。
3. 可信候选可“确认并锁定”，生成受保护的人工点。
4. 不可信项先不确认，人工找正确画面；点“返回映射预览”恢复映射播放。

没有可靠录音位置的项按未知位置提示处理；上下文画面不能当作已匹配画面。缺板书区间应单独保留，不能强配到相邻文字或片头片尾。

“标记已核对”只改状态，不会修复映射。确认候选、创建/修改锚点才改变对齐。待核对清单是工作队列，不是质量证明。

## 9. 双轨细调与两个 5 秒场景

上轨是固定录音/字幕，下轨是可调板书。横轴始终是录音时间。可缩放全片、5 分钟、2 分钟、30 秒、10 秒；“回到播放头”移动视口。

按 `A` 标记录音时刻，`V` 标记**实际显示的源画面帧**，`P` 将画面配到录音。配对前检查两个标记值，尤其是核对模式或等待解码之后。

| 场景 | 应保存的配对 | 操作含义 |
| --- | --- | --- |
| 板书提前 5 秒，source 6 应在录音 11 出现 | target=11, source=6 | 将该画面点向右延后 |
| 板书落后 5 秒，source 11 应在录音 6 出现 | target=6, source=11 | 将该画面点向左提前 |

拖菱形只改 target，source 保持。源时间需用“当前锚点”数值输入并“应用数值微调”。看两侧倍速和“映射检查”，避免倒序或小于一帧的段。

锁定点必须先明确解锁。人工配对越过密集自动点时，可能要求确认释放冲突的未锁定自动点；人工和锁定点不能静默丢弃。大改前保存副本。

| 快捷键 | 功能 |
| --- | --- |
| Space | 播放/暂停 |
| A / V / P | 标记录音/标记实际画面/一键配对 |
| L | 选中锚点附近局部循环 |
| 左/右 | 前后移动一帧，Shift 为 1 秒 |
| Ctrl+Z / Ctrl+Y | 撤销/重做 |
| Alt + 拖动 | 暂停吸附 |

输入框有焦点时不会触发编辑快捷键。浏览器显示帧、原视频帧格和输出帧格可能不同，精调后应短段导出核对。

## 10. 独立裁剪与 source 跳变

裁剪只去掉板书源片段，不删录音，不移动字幕。

1. 在“板书裁剪”填源起点/终点秒数，或用“当前帧”取值。
2. 填“录音跳变位置”；留空时应用按当前映射定位。
3. 被裁区间有人工作点时，明确决定是否允许暂存。
4. 点“提交板书裁剪”，检查裁剪列表、跳变前后和映射提示。

裁剪保存为独立 cuts。source 在指定 target 处右连续跳变。例如裁掉 source 6–10、target=6，则 target 刚到 6 时 source=10，之前仍来自裁剪前。

| 被裁点 | 处理 |
| --- | --- |
| 未锁定自动点 | 暂存到裁剪记录，退出活动点集 |
| 人工点 | 默认阻止；勾选“允许暂存被裁区间的人工点”后保存原 ID、来源、备注等 |
| 锁定点 | 阻止，需先明确解锁；人工暂存选项不绕过锁定 |

在裁剪列表恢复时还原暂存点。若后续编辑造成 ID、顺序或映射冲突，恢复整体失败，当前项目保持；先解决冲突或回到裁剪前副本，不要手工只删一部分 JSON。非法或重叠裁剪会被拒绝。

请检查跳变前、跳变处、跳变后，确认不显示被裁画面、字幕时基不动，并导出验证。

## 11. 定格与缺板书处理

两个 target 不同、source 相同的相邻点表示定格。例如 target 16/source 20 和 target 20/source 20，最后 4 秒保持 source 20。

可通过 CSV 重复 source，或面板修改数值。配对时也可在较晚录音位置复用同一实际画面，注意保留定格起点，避免改变前段速度。target 仍递增，区间至少一输出帧。

旁白长于板书时可人工定格片尾；缺板书是缺内容，不应把定格当自动匹配成功。终点 source 应指向能解码的有效帧，避免视频之外。

## 12. 保存与恢复

“保存项目”写入 `.align.json`：媒体引用、锚点、字幕、独立裁剪/暂存点、分析与核对状态。修改后需再次保存；刷新和关页不会自动保存。

重新启动点“打开项目”。相对路径以项目目录为基准；移动媒体后重新选择路径、载入、另存。项目可能含个人绝对路径和课程文字，不应公开提交。

不会保存整个撤销历史、播放位置和所有临时界面状态；重新打开会重置。CSV 不替代完整 JSON。建议粗调完成、人工核对完成、导出前分别存副本。

分析异常后可查看任务目录的 `project-before.align.json`、`project-after.align.json`、日志和状态；仅存在且完整的文件可恢复。未保存的手工编辑不保证崩溃恢复。

## 13. CSV / SRT / MP4 导出

“对齐表 → 另存 CSV”输出当前锚点及独立裁剪记录。重新导入要指定媒体，完整字幕与核对状态仍用 JSON。

“导出成片”同步生成同名 SRT，时间固定为旁白时基。它是旁挂文件，不应假定已烧录画面或嵌入 MP4；在播放器中加载 SRT 检查。单独需要字幕时可取导出生成的 SRT。

MP4 流程：
1. 消除阻断映射错误，核对末尾 target 与旁白实际包时长。
2. 保存项目，点“导出成片”，选择新的输出路径。
3. 默认选 `libx264（兼容，CPU）`，再点“开始导出”。
4. 等待“导出及 AAC 校验通过”，检查关键配对、裁剪、定格、片头片尾和字幕。

视频重新编码，音频 `-c:a copy`，不伸缩录音。输出通常有同名 `.mp4`、`.csv`、`.srt`、`.align.json`、`.ffgraph`、`.export.log`。失败或取消可能留下部分 MP4 和先写出的配套文件；只有成功与校验通过才算完整交付。不是任意把旁白压成指定片长的工具。

## 14. AAC 包内容与时间戳校验

导出后自动比较原 AAC/M4A 和成片首条音频流的 codec、time_base、起点、包数量、内容摘要、PTS/DTS/包时长和实际包时间线时长。听感或文件大小相同不够；重新封装后整个文件 hash 不要求相同。

独立复核：

```powershell
.\verify-audio.cmd "D:\Media\narration.m4a" "D:\Media\final.mp4"
```

或：

```powershell
py -3.12 -m alignstudio.mp4aac "D:\Media\narration.m4a" "D:\Media\final.mp4"
```

JSON `ok: true` 且退出码 0 表示通过，不一致为 1。要保存报告可执行：

```powershell
py -3.12 -m alignstudio.mp4aac "D:\Media\narration.m4a" "D:\Media\final.mp4" | Out-File -Encoding utf8 "D:\Media\aac-check.json"
if ($LASTEXITCODE -ne 0) { throw "AAC verification failed" }
```

AAC 延迟和 edit list 可能使容器声明时长不同于实际包时长，校验以实际包为准。不应通过重编码、改时间戳或忽略差异消除校验失败。

## 15. 合成演示

Release demo ZIP 只有测试图案与 440 Hz 音调，无课程或语音。解压后打开 `demo.align.json`；另有 `ahead-5s`、`behind-5s`、`cut` 项目。

自行生成：

```powershell
py -3.12 scripts\make_demo.py --ffmpeg "D:\Tools\ffmpeg\bin\ffmpeg.exe"
```

打开 `examples/generated/demo.align.json`。演示可验证编辑/导出，不评估语义粗调质量。更多方法见 [VERIFYING.md](VERIFYING.md)。

## 16. 故障排查

| 现象 | 处理 |
| --- | --- |
| 双击后关窗、py 不存在 | 在 PowerShell 手动运行，安装完整 3.12，多版本用 py -3.12 |
| 文件选择失败 | 用 -m tkinter 检查 Tcl/Tk，避免嵌入式 Python |
| “载入素材”不可点 | 先自动粗调或导入 CSV 创建项目 |
| 找不到 FFmpeg、波形失败 | 显式选 ffmpeg.exe，检查路径、权限和解码支持 |
| 浏览器 HEVC 黑屏 | 使用 FFmpeg 兼容预览，约 2 fps；检查实际帧提示 |
| 极速段预览跳帧 | 浏览器播放率有限，可能使用逐帧预览；短段导出核对 |
| 缺分析包 | 指定正确 venv 的 Python，正常 venv 不填额外库目录 |
| 缺模型 | 分别准备 Whisper/OCR/E5，模型栏选目录 |
| 下载或 pip 失败 | 检查网络、代理、Python 版本和空间，不跳过 SHA 检查 |
| 仅缓存报缺数据 | 取消仅缓存，冷跑当前身份；旧 v1 不能当 v2 |
| 20 秒仍有大量待核对 | 加密抽帧不保证准确，听录音并查看真实源帧 |
| 核对画面不随录音走 | 核对帧会保持，点“返回映射预览” |
| 锚点拖不动、裁剪失败 | 看锁定、人工暂存选项、顺序、重叠和一帧限制 |
| 恢复裁剪冲突 | 保存现状，处理新点/ID 冲突或回到旧 JSON |
| 终点与旁白相差超过一帧 | 核对同一 AAC 的实际包时长，修正末点，必要时延长定格 |
| NVENC 失败 | 选 libx264，另查硬件驱动 |
| 导出失败/AAC 不一致 | 看 export.log，确认原 AAC 路径，保留报告，不交付残留 MP4 |
| 项目找不到素材 | 以 JSON 目录解析相对路径，重新选择并另存 |
| Ctrl+Z 不生效 | 离开输入框；重新打开项目不恢复撤销历史 |
| 占用空间大 | 保存项目和必要结果后，自行清理不再使用的缓存/导出 |

反馈故障时附版本、Python/FFmpeg/分析库版本、复现步骤及脱敏错误。素材、字幕、OCR、项目和日志可能含个人路径或课程内容，分享前检查。

## 17. 已知限制

- 固定单条旁白时基，不提供任意音频剪辑和时间伸缩。
- 自动匹配受 OCR、同音词、讲解顺序、静态画面影响，未知区间必须人工判断。
- 内容支撑覆盖、置信分、全片插值不是同一指标；缺板书不能靠强配解决。
- 跨硬件/运行时 INT8 不承诺逐位相同，缓存据身份失效；同身份冷/热才可直接比较。
- 外部 ASR/OCR 的真实来源由使用者保证。
- 当前 AAC/M4A 逐包闭环不覆盖 WAV/MP3、多音轨选择或烧录字幕。
- 预览有性能/浏览器限制，导出有输出帧格量化；需检查实际输出。
- 模型、FFmpeg、分析环境不随源码分发，首次需网络和独立资源准备。
- 没有云同步、协作合并或自动备份；不承诺未保存操作崩溃恢复。
- 项目尚未指定开源许可证。公开源码不包含私人课程和历史失效验收证据。
